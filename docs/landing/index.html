The pipeline

From your art to a real cartridge.

The SNES does not eat PNGs, Tiled maps or WAV files — it eats tiles, BGR555 palettes and BRR samples. OpenSNES ships the tools that bridge the two, and the build system chains them for you.

Why it feels solid

A real toolchain, not a wrapper.

Compile

C11 all the way to the ROM

A genuine C compiler (cc65816 = cproc + QBE) targets the 65816, with fixed-width types, a documented ABI, and a linker that lays out banks for you. No assembly required — though it is there when you want it.

Verify

Cycle-accurate tests

Every example is exercised by a cycle-accurate emulator on each change — liveness, visual regression against baselines, and functional probes. SA-1, Super FX and DSP-1 all run natively.

Learn

Docs that build confidence

60 worked examples on a guided learning path, 31 tutorials, a game-craft track for the design decisions, and a documented tool for every asset — so the hard parts are written down, not discovered at runtime.

60-second start

Hello, Super Nintendo.

A complete ROM is a short main.c and a five-line Makefile. The build finds your assets, links only the modules you name, and writes a .sfc.

  1. Write your game in CInit the console, load your art, run a frame loop at 60 Hz.
  2. Name what you linkList the modules you use — the resolver pulls their dependencies.
  3. makeAssets convert, C compiles, banks link. Out comes a cartridge.
 main.c
#include <snes.h>

int main(void) {
    consoleInit();
    setMode(BG_MODE1, 0);
    // load palette, tiles, tilemap…
    setScreenOn();

    while (1) {
        // read pad, move sprites, update state
        WaitForVBlank();
    }
    return 0;
}
 Makefile
TARGET      := game.sfc
USE_LIB     := 1
LIB_MODULES := console sprite dma input
CSRC        := main.c
include $(OPENSNES)/make/common.mk
