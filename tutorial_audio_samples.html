Samples, Voices and the Raw APU

Choose this page for sound driven from C: the audio module plays BRR samples on the eight voices and drives the DSP's envelopes and echo, and the apu module runs an SPC700 program of your own. For tracker music, read Music with SNESMOD instead.

The audio module

LIB_MODULES += audio gives you the full engine with no SPC700 code of your own: the lib ships a resident driver (built from source at lib build time) and audio.h's functions drive it — audioInit(), audioLoadSample() (BRR streamed into APU RAM at runtime), audioPlaySampleEx() (volume/pan/ pitch, 8-voice round-robin polyphony), per-voice ADSR/GAIN, and a configurable echo with FIR filter. Every call is bounded — the API returns AUDIO_ERR_TIMEOUT rather than hanging. Worked example: audio/soundboard (soundboard — the audio v2 engine, driven entirely from C). Main-thread only; one engine per ROM (don't link audio and snesmod together).

One-shot samples from WAV

A plain one-shot effect — a jump, a hit, a UI blip, a bit of speech — is a direct BRR sample: convert an audio file to the SNES's BRR format once, bake it into the ROM, and trigger it from C. This is what SFX from WAV does.

1. Put a settings file beside the WAV. opensnes-sample — WAV to BRR samples turns a PCM .wav into a .brr using the same encoder opensnes-music — Impulse Tracker to soundbank uses on a module's samples, and the build runs it for every settings file that names it:

# res/jump.wav.toml — a one-shot effect
tool = "opensnes-sample"
[encode]
# res/cello.wav.toml — a looping sample (loop between sample indices 2048 and 8192)
tool = "opensnes-sample"
[encode]
loop = [2048, 8192]

Input is PCM WAV (8- or 16-bit, mono or stereo — stereo is downmixed). Keep the source at or below 32 kHz; that is the DSP's ceiling, and a higher rate plays back lower and slower (the tool warns, and says by how much). opensnes-sample inspect res/jump.wav prints the block count and the audio RAM a sample costs without writing anything.

2. The build bakes the .brr into the ROM. opensnes-sample encode runs before the first C object; it writes res/jump.brr, a res/jump_data.as the build links (its own ASSET_SECTION, so any bank but $00), and a res/jump.h that declares jump_brr[], jump_brr_end[], the size (jump_brr_size) and the loop point (jump_brr_loop, a byte offset; 0 for a one-shot).

3. Load it once, play it on demand:

#include "res/jump.h"
audioLoadSample(0, jump_brr, (u16)(jump_brr_end - jump_brr), jump_brr_loop);
// ...later, when the player jumps:
audioPlaySample(0);

Loading while the game runs

audioLoadSample() returns when the whole sample is in the sound CPU's memory: about 650 master cycles a byte, so a 5.6 KB voice stops the game for ten frames. Fine under a title screen; not during play. To swap a sample during play, send it a piece a frame:

audioLoadSampleBegin(SMP_VOICE, replay_brr, (u16)(replay_brr_end - replay_brr), 0);
loading = 1;
// ...in the game loop, once a frame:
if (loading && audioLoadSampleStep(64) == 0) {
loading = 0; /* whole: SMP_VOICE can be played */
}

Voices that are playing go on, and audioPlaySample(), volume, pitch and stop commands pass between two steps. The slot cannot be played before a step returns 0. One sample at a time; audioUnloadSample() on it gives the load up.

What a step costs, measured on luna (interrupts included): about 18,700 master cycles whatever its size (four commands and the end of the transfer), plus about 650 a byte. Bytes travel three at a time, so a step is a multiple of 3:

maxBytes Sent Master cycles Share of a frame
64 63 59,750 17 %
128 126 100,800 28 %
256 255 184,750 52 %

A 5.3 KB voice is whole in 85 frames at 64 bytes a frame.

Choosing the voice

audioPlaySample() and audioPlaySampleEx() pick a voice round-robin and return it (or AUDIO_VOICE_NONE). audioPlaySampleOn(voice, sample, volume, pan, pitch) plays on the voice you name — reserve one for a long sound that must not be cut by the next effects, and shape its envelope before the key-on:

#define VOICE_ENGINE 7
audioSetADSR(VOICE_ENGINE, 4, 7, 7, 0); /* slow attack */
audioPlaySampleOn(VOICE_ENGINE, SFX_ENGINE, 90, AUDIO_PAN_CENTER, 0x1000);
/* ... */
audioStopVoice(VOICE_ENGINE); /* key-off */

Each command is a handshake with the driver, so one call instead of two is what counts: four voices updated every frame cost about 10 600 master cycles a voice with the two calls and 5 500 with this one, measured on luna. The volume is split between left and right by the voice's pan — the one audioPlaySampleOn() gave it, or the one audioSetVoicePan() set since — exactly as audioPlaySampleOn() splits it, so a voice that plays hard left stays hard left.

Shaping the envelope: ADSR or GAIN

audioSetADSR(voice, attack, decay, sustain, release) gives a voice the classic envelope (the AUDIO_ATTACK_*, AUDIO_DECAY_*, AUDIO_SUSTAIN_*, AUDIO_RELEASE_* constants). audioSetGain(voice, mode) switches the voice to GAIN instead and writes mode to its GAIN register as is: $00-$7F hold the envelope at a fixed level (value × 16); with bit 7 set, bits 5-6 choose linear decrease, exponential decrease, linear increase or bent increase, and bits 0-4 the rate (snesdev-wiki, S-DSP registers, VxGAIN; anomie's S-DSP doc). They shape the attack, so set them before playing on that voice — which is why audioPlaySampleOn() lets you choose it.

audioSetGain(2, 0x7F); /* voice 2 at a steady full level */
audioSetGain(2, 0xC0 | 20); /* voice 2 fades in linearly */

Echo

Echo takes three steps, in this order: the delay and levels, the filter, then the voices that feed it.

static const s8 fir_flat[8] = { 0x7F, 0, 0, 0, 0, 0, 0, 0 };
audioSetEcho(4, 40, 50, 50); /* 64 ms, feedback 40, volume L/R */
audioSetEchoFilter(fir_flat);
audioEnableEcho(0x03); /* voices 0 and 1 */
/* ... */
audioDisableEcho(); /* mutes the echo and stops the ring writes */

{ 0x7F, 0, 0, 0, 0, 0, 0, 0 } is the identity filter: the echo comes back unfiltered (snesdev-wiki, S-DSP registers, FIRx, which also says to set the filter before echo is enabled). audioSetEcho() takes the top of the sound CPU's memory for the echo ring, 2 KB per unit of delay, and answers AUDIO_ERR_NO_MEMORY when samples already loaded are in the way: a game short of sample memory sets its echo before it loads, and keeps the delay short. The call blocks: the driver waits for the ring it replaces to run out (up to 240 ms the first time, 16 ms per unit of the previous delay after) and clears the new one. Call it when a scene starts, never during play. audioDisableEcho() then audioEnableEcho() is the cheap way to turn the same echo off and on; the ring keeps its memory meanwhile.

A game that wants an echo in one scene only gives the ring back when the scene ends:

audioReleaseEcho(); /* echo off, the ring's memory back to the samples */
/* samples may be loaded where the ring was as soon as it returns */
audioReleaseEcho
u8 audioReleaseEcho(void)
Turn the echo off and give its ring back to the samples.

The next audioSetEcho() takes a ring again, with the same wait, and answers AUDIO_ERR_NO_MEMORY if samples loaded in between are where it goes: unload them first.

Asking the engine

Call Returns
audioIsReady() 1 once audioInit() has started the driver; 0 if the driver did not answer
audioGetFreeMemory() bytes left for samples in the SPC700's RAM
audioGetVoiceState(voice, &state) whether the voice's envelope is still sounding, and the sample, volume, pan and pitch last sent to it

There is no per-frame audio call: the engine sends each command as you call it, nothing is deferred.

The raw APU path

The apu module uploads a wla-spc700-assembled program straight through the IPL boot-ROM protocol — apuWaitBoot(), apuUpload(), apuExecute() — giving full DSP control (voices, ADSR, echo, pitch) with no tracker involved. Worked example: audio/speech_synth (phoneme-bank speech — upload, DSP config, per-phoneme sequencing). Like audio, it is never linked with snesmod in one ROM.

APU-side memory layout matters: the flat binary is laid out by wlalink -b, and an .ORG section that overlaps your growing code OVERWRITES it silently. Budget the code page before placing the sample directory.

Hot-swapping APU programs

apuWaitBoot() only works once — the IPL handshake is consumed at boot. To replace the running program later, use the cooperative reset protocol (worked example: audio/apu_switch):

  1. Build the APU program with APU_CHECK_RESET (from templates/memmap_spc700.inc) inside its wait loops. The idiom polls CPUIO0 for APU_RESET_MAGIC; on match it silences the DSP, acks, re-enables the IPL ROM and jumps to $FFC0 — the boot ROM is re-entrant.
  2. On the 65816, call apuReset(), then apuUpload()/apuExecute() for the next program — but NOT apuWaitBoot() (the reset already consumed the ready signal).

Two contract points, both shown by apu_switch: apuReset() blocks forever on a program that never polls for the magic, and the next program receives the DSP dirty — a residual ADSR1 bit 7 from the previous program silently overrides GAIN, so every register a voice depends on must be written explicitly.

Debugging audio: luna's spc-dump

luna spc-dump runs a ROM and exports the complete APU state — 64 KB of ARAM plus all 128 DSP registers — as a standard playable .spc. Diffing two dumps (yours vs a reference, or two instants of your own ROM) answers in seconds what ears cannot localize: upload integrity, directory/loop addresses, per-voice ADSR/pitch/envelope state, phoneme/note schedules. --audio-out (WAV capture) complements it for spectral verification.
