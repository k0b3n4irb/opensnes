Fade and Mosaic — Screen Transitions
Demo
Screenshot

The two transitions the PPU gives for free: a brightness fade and the mosaic filter. Press any button to step through them: fade out and in at three speeds, then the picture breaking into growing blocks and sharpening again.

Learning Objectives

After this lesson, you will understand:

  • How master brightness works, and why brightness 0 is not force blank
  • How the mosaic filter groups pixels into blocks, and on which layers
  • How the speed of a transition is set, and what it costs (nothing but one register write per step)
  • How the two combine into the classic RPG battle transition

SNES Concepts

  • Master brightness, INIDISP ($2100) bits 0-3; force blank, bit 7
  • The mosaic filter, MOSAIC ($2106): block size and per-layer enable
  • Frame-paced transitions: one register write per step, timed by VBlank
  • Sprites are not mosaicked; backgrounds are

Prerequisites

  • A background on screen (backgrounds/mode1)
  • VBlank timing (basics/game_skeleton)

How It Works

1. Brightness: INIDISP ($2100)

fadeOut(1); /* 15 -> 0, one step per frame: a quarter of a second */
fadeIn(3); /* 0 -> 15, one step every 3 frames */
fadeIn
void fadeIn(u8 speed)
Fade the screen from black (0) up to full brightness (15).
fadeOut
void fadeOut(u8 speed)
Fade the screen from full brightness (15) down to black (0).

Bits 0-3 of INIDISP are the master brightness, 0 (black) to 15 (full); bit 7 is force blank. fadeOut(speed) and fadeIn(speed) (snes/console.h) step the brightness once every speed frames:

Speed Frames per step Whole fade
1 1 15 frames, 0.25 s
3 3 45 frames, 0.75 s
6 6 90 frames, 1.5 s

Brightness 0 is not force blank. The screen is black but the PPU still draws, so VRAM is still closed outside VBlank. To load a new scene, fade out, then setScreenOff(), load, setScreenOn() and fade in.

2. Mosaic: MOSAIC ($2106)

mosaicSetLayers(LAYER_BG1); /* which backgrounds the filter applies to */
mosaicFadeOut(3); /* block size 1x1 -> 16x16, 3 frames per size */
mosaicFadeIn(3); /* 16x16 -> 1x1 */
mosaicDisable(); /* size 0 and no layer: the filter is off */
LAYER_BG1
#define LAYER_BG1

Animate mosaic fade in (pixelated -> clear).
mosaicFadeOut

Animate mosaic fade out (clear -> pixelated).
mosaicDisable
void mosaicDisable(void)
Disable mosaic effect for all backgrounds.
mosaicSetLayers
void mosaicSetLayers(u8 bgMask)
Set the backgrounds the mosaic applies to — REPLACES the previous set.

Bits 7-4 of MOSAIC are the block size minus one (0 = 1x1, 15 = 16x16), bits 3-0 the background layers it applies to. Each block takes the colour of its top-left pixel: the picture looks like a lower resolution of itself, it is not a blur. Sprites are never affected — only backgrounds — so characters can stay sharp while the scene dissolves behind them.

3. Combining both

The classic battle transition of SNES RPGs:

  1. mosaic out (the scene turns into blocks),
  2. fade to black,
  3. load the new scene in force blank,
  4. fade in (still blocky),
  5. mosaic in (the blocks shrink and the new scene appears).

Build & Run

cd $OPENSNES_HOME
make -C examples/transitions/fading

Then open fading.sfc in luna (luna-gui fading.sfc) or any emulator.

Exercises

  1. Scene change: load a second picture and switch to it with the five steps of section 3.
  2. Per-layer mosaic: put a second background on BG2 and mosaic BG1 only.
  3. Colour fade: fade to white instead of black with colour math (color/transparency).
