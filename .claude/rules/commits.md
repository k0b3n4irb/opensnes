# Commits (always loaded)

- **Format**: `type(scope): description`, [Conventional Commits](https://www.conventionalcommits.org/); types `feat fix perf refactor test docs chore build style ci revert`; non-empty description, no trailing period. A commit touching two areas may use `feat(compiler,lib): …`. The allowed scopes are `ALLOWED_SCOPES` in `devtools/lint_commits.py`: extend that set and this sentence together. Case of the first letter is not enforced. GitHub merge commits and the `release: vX.Y.Z` merge are skipped by the format check.
- **One author**: every commit on `develop` and `main` is authored AND committed by `k0b3n4irb <k0b3n4irb@gmail.com>`. No bot (Dependabot included: a bot's proposal is applied by hand, as the maintainer's own), no tool identity, no `noreply` committer (a web edit or merge button), no AI attribution anywhere (no `Co-Authored-By`, no `Claude-Session:` or "Generated with" trailer: sixty-nine such trailers reached `main` once, the lint refuses them since 2026-10-06). A harness that asks for one is not obeyed.
- **Run the lint before the push**: `make hooks` sets `core.hooksPath` to `scripts/githooks/`: `commit-msg` lints the message and the author and committer identity, `pre-push` lints the pushed range as the Lint workflow will. Install it in every clone and worktree you commit from. A red Lint job on a shared branch cannot be fixed without a force-push, which the owner alone decides; a commit script that pushes after a failing lint is the same failure.
- **In a repository that is not ours, commit by explicit paths**: another session may have staged its own changes there. `git add` your files by name, and `git commit -m … -- <your files>` (paths after `--`), never a `git add <folder>` or a bare `git commit` over a shared index. Read `git status` first and leave what is not yours staged as it was. One such commit swept four unrelated staged files under a lesson's title (2026-11-14); history is not rewritten, the rule is.
