# Calling the most capable model (always loaded)

The owner's decision of 2026-11-14: the strongest model is very powerful but can stray, so it gets one simple, bounded task at a time and very precise instructions. Only this project may call it (rule of 2026-11-12, still valid), and only where the cheaper pair cannot do the job: the written contest of a compiler lot's plan, a diagnosis of one precise gap, the review of one diff before a lot that touches the whole corpus closes.

Every call follows four rules:
1. **One bounded task.** Never a whole lot, never an open mission. Examples: contest this plan; diagnose this one gap; review this one diff.
2. **A written instruction** that gives: the exact question; the files and pieces to read; what is out of scope; the form of the answer (a verdict, a list, figures, pieces to attach). Read-only unless the task says otherwise.
3. **The answer is verified.** Nothing is kept without its piece replayed (a measurement re-run, a line read, a test re-run). An answer that leaves the asked field is set aside and the instruction is tightened.
4. **The journal says when and why** the call was made, and gives the instruction (the resume note's section for the lot).
