## 1. What v1.21.0 carries

| item | what you get |
|---|---|
| **fbhash v2** | `fbhash` — `luna run`, `luna state --print-fbhash`, the manifest key, the MCP `frame_hash` tool — is now **FNV-1a 64** over the raw RGBA bytes of the displayed frame (offset basis `0xcbf29ce484222325`, prime `0x100000001b3`). Pinned; stable across toolchains and architectures by construction. |
| R-A seed pair | `luna test --report json` carries, per test, `"power_on": "random", "seed": 12345`. A deterministic run reports `"zero"` / `"ones"` with `"seed": null`; `random` without a seed reports `1`, the default it ran with. |
| R-C executed PCs | `luna profile --pc-set out.bin`: every distinct 24-bit PC that executed in the profiled window, **sorted**, one little-endian `u32` each. Whole 24-bit space as it ran — `$7E` WRAM code, `$80+` FastROM mirrors — fold the mirrors on your side. No `coverage` subcommand. |
| R-D second pad | `input2`, same `frame:hex` grammar as `input`, in the manifest (top level and per `[[checkpoint]]` leg) **and** on the CLI (`luna state --input2`). An MCP capture's `script_p2` replays headless. |
| `$43xx` under `--peek` | `$4300-$437F` returns the DMA channel file instead of the register band's `0`. Your crt0 probe: `luna state -n 200 --power-on random --peek 00:4300:10 game.sfc` → `FF …` for a crt0 that leaves them, `00 …` for one that clears them. |
| sprite line | unchanged since v1.20.0 — the rows will not move again (reference in this morning's §1). |

## 2. The migration, in order

1. Pin `v1.21.0`.
2. `luna test --update tests/` — regenerates every `fbhash` in place,
   formatting and comments preserved. **Every v1 value changes**; this is
   the one-time cost of the switch, and it folds the 26 sprite baselines
   into the same commit.
3. Commit the 85 + 50 + template together. Suggested message: "luna
   v1.21.0 — fbhash v2 (FNV-1a 64 over RGBA); sprite line per ares
   `object.cpp:16-22,57-61` / Mesen2 `SnesPpu.cpp:595-625`."
4. Optional, same commit: add `input2` to `input/two_players`, and switch
   your JSON consumer to read `power_on` / `seed` from the report.

Nothing else in v1.21.0 changes emulation. The golden suite's SHA-256 is
untouched; `rom_hash` is untouched (FNV-1a since the v5 state schema, 2026-08).
