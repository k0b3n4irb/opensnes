## 2. Super FX saves — and why your ROMs don't get one

**What changed in luna v1.30.3.** A Super FX cartridge with a battery now
has a save: the **whole GSU work RAM** (32 KB on Yoshi's Island, 64 KB on
Stunt Race FX and Star Fox 2). It is what ares and Mesen2 do: ares writes
the board's RAM unless it is volatile; Mesen2 saves `_gsuRam` when the
header says battery. The GUI writes it beside the ROM as `.srm`, and
`srm_out` / `srm_in` in `luna test` work for Super FX. A board without a
battery (Star Fox `$13`, Doom `$14`) has no save, as on a real cart.

**The battery is read from `$FFD6`:** low nibble `$2`, `$5`, `$6`, `$9` or
`$A` (Mesen2's rule). Yoshi's Island is `$15`, Stunt Race FX `$1A`.

**Your Super FX ROMs are all `$13`** (ROM + RAM, no battery):
`superfx_game_skeleton`, `superfx_3d`, `superfx_hello`, `libtest_gsu`.
That comes from `make/common.mk`, which sets `CARTRIDGETYPE` to `$13`
whenever `USE_SUPERFX=1`, **whatever `USE_SRAM` says**. So today a game
built with OpenSNES and the Super FX **cannot save**, on luna or on
hardware. If that is deliberate, nothing to do. If a Super FX game should
be able to save, `USE_SUPERFX=1 USE_SRAM=1` would need `$15`, with the
save living in GSU RAM at `$70:0000` (there is no separate SRAM on these
boards; `$FFBD` sizes it as `1024 << n`, so your `$06` gives 64 KB).

## 3. luna v1.30.4: MCP fixed for Claude Code 2.1.287

**Symptom.** Claude Code 2.1.287 negotiates MCP protocol `2026-07-28`.
`luna mcp` accepted it but left out two fields that version requires on a
`tools/list` result (`ttlMs`, `cacheScope`). The client rejected the whole
list: **all of luna's tools vanished from the session**, with only
"fetching tools failed: Invalid result for tools/list … ttlMs" on
reconnect.

**Fix.** It came from our MCP library (rmcp 3.1.0; 3.1.1 fixes it).
v1.30.4 sends both fields under `2026-07-28` and neither under older
versions; a protocol test checks both on the raw wire. The emulator is
unchanged.

If you drive luna over MCP from Claude Code, pin **v1.30.4**. If you only
use the CLI, v1.30.3 and v1.30.4 behave the same; v1.30.3 is the one that
adds the Super FX saves.
