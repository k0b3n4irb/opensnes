Detailed Description

LZ77 decompression into RAM, screen on: lzssDecodeRam.

lzssDecodeVram expands a compressed block straight into VRAM, which needs forced blank. lzssDecodeRam expands it into RAM instead, in any bank, with the screen on and the NMI running: the game decompresses its tiles while it plays, then sends them to VRAM by DMA in VBlank.

This example decodes, with the screen on, a 2 bpp tile block that opensnes-sprite compressed (32768 bytes from 17856) into bank $7F and into a FAR buffer of bank $7E, and compares each copy byte for byte with the same tiles converted without compression. Hand-built streams then check the edge cases: literals only, long references (also into the low 8 KB, the byte-loop copy), a reference cut at the end of the output, overlapping references (distance 1, distance shorter than the length) into $7F, $7E and the low 8 KB, a stream that ends exactly at the end of bank $7F, and four refused streams (length 0, length above 65535, a wrong tag, an output that would cross the end of the bank), each of which must return 0 and leave its destination as it was. The verdict of each test is in WRAM, for the luna manifest, and on screen.

SNES Concepts
  • LZ77 (type 0x10) decompression: flag bytes, literals, back references
  • The 128 KB of work RAM: bank $7E (FAR objects) and bank $7F
  • MVN block moves, and why an overlapping move repeats a pattern
  • Decompressing with the screen on: no PPU access, NMI left enabled
What to Observe
  • One line per test: its name, the bytes returned, OK or BAD
  • ALL OK at the bottom when every test passed
