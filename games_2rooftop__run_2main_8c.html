Detailed Description

Kit's Rooftop Run — a side-scrolling platformer, title to game over.

A complete platformer on the rooftops of the city at night: Kit, the fox-kit courier, runs from roof to roof to the radio beacon at the end of the level, picking up data shards and stomping the security machines on the way. Three lives; a fall between two roofs or a machine touched from the side costs one, and Kit comes back at the start of the last roof he reached. The game goes title → play → roof cleared or game over → title.

It shows the core techniques of a scrolling SNES game: tile-based map streaming, subpixel physics, tile collision, camera tracking, animated sprites, a parallax layer, a text HUD in front of everything, and SPC700 music and sound effects through SNESMOD.

The map engine streams one tile column per frame using a prepare/flush pattern: during active display, the next column is read from ROM into a RAM buffer (map_prepare_column) and noted in the VRAM queue; during VBlank, vramQueueFlush() sends it with one 64-byte DMA. This keeps VRAM writes within the VBlank budget. The column at +32 tiles ahead is streamed to cover the 33rd partial tile at the screen edge.

Kit and the machines are dynamic sprites: the engine gives each one drawn a 32x32 slot of VRAM in the order they are drawn, so all of them are drawn every frame, in the same order (a machine off screen or stomped is drawn hidden), and each one keeps its slot. The shards are plain 16x16 sprites whose eight frames sit once in VRAM, in the tiles the engine's last slots would use (it uses seven).

This began as the PVSnesLib likemario example; the level, the roofs, the skyline, Kit, the machines and the shards are ours (devtools/art_assets/build.py writes the level and its objects from the pictures in assets/neo-lumen/).

SNES Concepts
  • Scroll streaming: 1 column/frame prepare-during-display, DMA-in-VBlank
  • SC_64x32 tilemap with 64-column wraparound for seamless scrolling
  • Subpixel 8.8 fixed-point physics (acceleration, gravity, max velocity)
  • Tile collision via property lookup table (tilesetatt)
  • Dynamic sprites in stable slots, beside static sprites in the same OAM
  • Box collision between sprites, from above (a stomp) or from the side
  • A BG3 text HUD in front of BG1 and BG2 (BG3_MODE1_PRIORITY_HIGH)
  • A second layer scrolled at a quarter of the camera's speed (parallax)
  • SNESMOD: SPC700 module playback and five sound effects
  • A game state machine: title, play, a life lost, game over, cleared
What to Observe
  • START on the title screen starts the run
  • Kit walks left/right with acceleration and deceleration; A jumps (hold UP for a higher jump)
  • Shards spin; walking or jumping through one counts it, a chime plays
  • Landing on a robot insect or a drone flattens it and bounces Kit; touching one from the side, or falling, costs a life
  • Reaching the beacon clears the roof: the shards left give a bonus
Modules Used
console, sprite, sprite_dynamic, sprite_lut, dma, input, background, anim, vramqueue, text

Arithmetic right shift by 8 bits (extract integer part of 8.8 fixed-point).

cc65816's >> on a signed value IS arithmetic (compiler check test_signed_ops.c), so val >> 8 would do; this helper spells the sign handling out:

◆ main()

int main ( void )

Main entry point – initialization and the game loop.

Initializes all subsystems during force blank: Mode 1 video with BG3 in front, tiles and palettes by DMA, the dynamic sprite engine, the shard frames, the map, the text HUD and SNESMOD (music + five effects). Then the loop, a strict pipeline:

Active display (CPU-only, no VRAM):

  1. the state's work: the title waits for START, the run moves Kit and meets the shards and the machines, a life lost waits, the end waits for START
  2. Kit's animation and camera, the shards and the machines drawn
  3. map_update() - prepare next column in RAM buffer

VBlank (VRAM writes allowed):

  1. vramQueueFlush() - DMA the column noted (64 bytes)
  2. bgSetScroll() - update hardware scroll registers
  3. the NMI sends the OAM, the HUD when it changed, and the sprite tiles
  4. snesmodProcess() - SPC700 communication (no VBlank restriction)
Returns
0 (never reached – infinite game loop)

◆ map_get_tile_prop()

u16 map_get_tile_prop ( s16 px,
s16 py )
static

Look up the collision property of the tile at pixel coordinates.

Converts pixel coordinates to tile coordinates, reads the tile index from the map via precomputed row pointers, then looks up the tile's property (T_SOLID or T_EMPTY) in the attribute table. ◆ map_update()

void map_update ( void )
static

Check if the camera has scrolled to a new tile column and prepare it.

Compares the current camera tile position to last_tile_x. If the camera moved right, prepares the column at +32 (one tile ahead of the visible right edge, covering the 33rd partial tile). If moved left, prepares the newly revealed left column. At most one column is prepared per frame.
