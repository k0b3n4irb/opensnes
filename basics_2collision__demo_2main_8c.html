Detailed Description

AABB and tile-based collision detection with visual feedback.

Demonstrates the OpenSNES collision module with two complementary techniques: axis-aligned bounding box (AABB) tests between sprites, and tile-based collision against a map. Kit walks through a warehouse of the Rue basse, between wall plates and stacks of crates, while four security drones hover at fixed places. Collisions are detected every frame: a drone Kit touches turns its lights green. Wall collisions use corner-point checks against a 16x14 collision map of 16x16 cells, with per-axis rejection so that Kit slides along walls.

The collision map is also the picture: the example builds BG1's tilemap from it at boot (a wall plate, a crate or the floor for each cell), so what Kit bumps into is exactly what is drawn.

A hitbox is not a sprite. Kit is a 32x32 sprite; what collides is a 16x16 box at his feet, and the sprite is drawn around it. The drones' boxes are their bodies, smaller than their frames too.

SNES Concepts
  • AABB collision via collideRect() for sprite-vs-sprite overlap testing
  • Tile collision via collideTileEx() (16x16 cells) for sprite-vs-map wall rejection
  • A tilemap built from game data in force blank: one DMA a row
  • A hitbox smaller than its sprite, and the sprite drawn from the box
  • A palette per state: the same tiles, OBJ palette 1 or 2
What to Observe
  • Walk Kit with the D-pad: he faces the way he walks (left is his right frames mirrored) and takes steps while he moves
  • He cannot pass through the crates or the walls; he slides along them
  • When his box overlaps a drone's, the drone's lights turn green
  • Two drones can be touched at once; each is tracked on its own

void build_tilemap ( void )
static

Build BG1's tilemap from the collision map, in force blank.

Each cell is 2x2 tiles of res/cells.png: cell k of the picture (0 floor, 1 crate, 2 wall, 3 floor with a drain) is tiles 2k, 2k + 1 above 8 + 2k, 9 + 2k. A floor cell gets the drain now and then, chosen from its position so the floor is not one repeated slab. One row of 32 map entries is built in RAM and sent with one DMA, 28 times.

Test whether Kit's box at a position would overlap a solid cell.

Probes the four corners of the 16x16 box against collision_map[] via collideTileEx() with 16-pixel cells. If any corner lands on a solid cell, the function returns 1 to reject the movement.

The caller uses per-axis rejection: if the combined (new_x, new_y) collides, it tries each axis independently so that Kit slides along walls instead of stopping dead.

◆ frame_tile()

u16 frame_tile ( u16 f)
static

The OAM tile of frame f of res/cast.png.

A 32x32 frame is 4x4 tiles and a row of OBJ tiles is 16 wide, so frame f (four a row of the sheet) starts at column (f % 4) * 4 of tile row (f / 4) * 4. Frames 16 and up are past tile 255: the second OBJ name table, which oamSet() reaches through the tile's ninth bit.

int main ( void )

Entry point – build the warehouse, run the loop with collision tests.

Sets up Mode 1 with BG1 for the warehouse and sprites for Kit and the drones. The main loop reads the D-pad every frame, proposes a new position, validates it against the wall collision map (with per-axis sliding), checks AABB overlaps with the drones, and places the sprites. The NMI handler sends the OAM buffer during VBlank.

◆ update_sprites()

void update_sprites ( u8 moving)
static

Place the five sprites from their hitboxes.

The drones take OAM slots 0-3 and Kit slot 4: the lower slot is drawn in front, and the drones fly, so a drone Kit walks under stays visible — its green lights are the feedback. Kit's 32x32 frame is drawn so that his 16x16 box sits at its bottom centre (8 pixels in, 16 down): his feet. The drones' boxes sit 8 pixels into their frames each way, round their bodies. Kit walks while he moves (five frames, six vblanks each) and stands on the first frame of his direction otherwise; the drones hover through four frames together.

Tile-based collision map (16x14 = 224 bytes, 256x224 pixels).

Row-major, one byte a cell: FLOOR is passable, CRATE and WALL are solid (collideTileEx() returns the value; the example only asks "non-zero"). The two solid kinds differ only in how they are drawn.

Note
const, so it lives in ROM and costs zero WRAM. collideTileEx() takes a const u8 *, and const-qualified loads compile to bank-honouring far reads — the map may sit in any bank.
