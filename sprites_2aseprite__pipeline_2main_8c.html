Detailed Description

End-to-end Aseprite sprite pipeline: art + timeline → animated metasprite.

This example animates a 32×48 hero metasprite whose every byte of data is machine-generated from a single Aseprite project — no hand-authored frame tables, no hand-typed animation clips. It is the working reference for the two-tool sprite pipeline:

hero.aseprite ─┬─ gfx4snes -P → hero.pic/.pal + res/hero_meta.inc │ (tiles, palette, metasprite pointer table) └─ aseprite2snes → res/hero_anim.h (one AnimClip per Aseprite tag)

gfx4snes owns the pixels and the metasprite geometry; aseprite2snes owns the timeline (tags, per-frame durations, direction) that indexes it. They meet at the frame value: a clip's frame i selects hero_metasprites[i], resolved inline by animTickMeta().

The artist authored two tags in Aseprite — walk (forward loop) and wave (ping-pong) — with per-frame millisecond durations. aseprite2snes converted those to ticks and folded the ping-pong into the frame order; press A to toggle between the two generated clips.

SNES Concepts
  • Metasprite composition from multiple OAM entries (oamDrawMeta)
  • The anim.h player driving a metasprite via animTickMeta()
  • OBJSEL size mode + OBJ VRAM base for 16×16 hardware sprites
  • Sprite palette at CGRAM 128 (OBJ_CGRAM_BASE)
What to Observe
  • A hero walks in place (4-frame cycle, per-frame timing from Aseprite)
  • Press A to toggle to the ping-pong "wave" clip and back
  • The text label shows which generated clip is playing
