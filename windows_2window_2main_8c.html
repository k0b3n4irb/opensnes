Detailed Description

An HDMA-shaped window: a torch beam in a dark alley, masking layers or lighting them.

Kit stands in a dark back alley with a torch. The beam is a window: its left edge (WH0) changes on every scanline, driven by HDMA, so the window is a cone that leaves the torch and opens to the right. Two backgrounds are loaded — the alley (BG1) and the rain falling in front of it (BG2) — and the buttons choose what the beam does to them.

HDMA channels 4 and 5 drive WH0 ($2126) and WH1 ($2127) in repeat mode, updating the left and right window boundaries every scanline. The W12SEL register ($2123) controls which BG layers are affected by Window 1, with the invert bit set so pixels outside the beam are masked (clipped to black). Kit is a sprite, and the window is not enabled on sprites: he stays visible in the dark.

The same window has a second use: instead of hiding layers, it can mark where colour math happens. Press Y and the beam stops clipping and lights instead — colour math adds a warm fixed colour inside it only (CGWSEL "inside the colour window"), the way a game draws a light, a shadow or a dialogue box over the scene.

Ported from PVSnesLib's "Window" example; the colour-math mode is its "TransparentWindow" example (by Digifox), adding instead of subtracting.

SNES Concepts
  • Window masking via W12SEL ($2123) and TMW ($212E) registers
  • HDMA repeat mode for per-scanline WH0/WH1 updates, the table computed at boot from the shape it draws
  • Window inversion (mask outside vs inside the region)
  • Runtime window reconfiguration via register writes
  • The colour window (WOBJSEL) as the region of colour math (CGWSEL/CGADSUB)
  • Fixed colour source (COLDATA, $2132) added to brighten
What to Observe
  • At boot the alley and the rain are black but for the torch's beam
  • Press A: the beam on the alley only — the rain falls everywhere
  • Press X: the beam on the rain only — the alley is lit, the rain shows only where the torch catches it
  • Press B: the beam on both again
  • Press Y: nothing is clipped, and the beam brightens what it falls on

◆ setup_light()

void setup_light ( void )
static

Use the beam as the region of colour math instead of a mask.

The HDMA tables are the same; what changes is what the window is for. No layer is clipped (TMW = 0): the colour window, not inverted, is the beam, and colour math adds a warm fixed colour (6, 5, 2) to BG1 and BG2 inside it only (CGWSEL bits 5-4 = 01). PVSnesLib's TransparentWindow subtracted, to darken; adding lights.

◆ setup_window()

void setup_window ( u8 layers,
u8 w12sel_val )
static

Configure HDMA-driven window masking on the specified BG layers.

The window "inverts" masking (via the invert bits in W12SEL), so pixels OUTSIDE the beam are clipped to black, while pixels inside remain visible. This is the opposite of the default behavior (which masks inside).

HDMA channels 4 and 5 are used (not 7, which carries every DMA of the NMI handler). HDMA is disabled before reconfiguration and re-enabled after to avoid partial-table reads during the transition.

Parameters
layersBitmask of BG layers for TMW (e.g., TM_BG1 | TM_BG2)
w12sel_valW12SEL register value specifying which BGs use Window 1

u8 tablelefttriangle[2+1+(224 -(187 - 70))+1]

HDMA table for the left window boundary (WH0, $2126).

BEAM_TOP lines with WH0 = 255 (left > right: no window), then one value a line for the beam — BEAM_X + 3 x |line - BEAM_Y|, the cone's edge, or 255 where that is past the screen — then the end of the table.

◆ tablerighttriangle

u8 tablerighttriangle[2+1+(224 -(187 - 70))+1]

HDMA table for the right window boundary (WH1, $2127).

The cone reaches the right edge of the screen on every line it covers: WH1 = 255 there, and 0 (no window) above it.
